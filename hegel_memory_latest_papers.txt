Hegel 调研备忘录：最近 memory / long-term agent memory 论文与社区看法
生成日期：2026-04-26
范围说明：以下内容整理自前面 Hegel 对 SimpleMem 相关工作的调研，重点覆盖 2026-02-26 至 2026-04-26 附近的近期工作；少量 2026-01 / 2026-02 初的论文作为核心 baseline 或关键背景保留。


一、先给结论

1. 不能把 arXiv 摘要里的 SOTA 当事实。
这些论文里的分数和 SOTA claim 都只能写作“作者报告”或“论文声称”。
真正可信的 SOTA 应该是本地可复现、统一协议、统一模型、统一评测脚本下的 controlled baseline。

2. 对当前项目来说，SimpleMem 仍然是最重要的主 baseline。
但 SimpleMem 不是唯一应该比较的对象。
必须加入 raw dialogue retrieval、BM25 / keyword、full-context LLM 等简单强 baseline。

3. 最近两个月 memory 领域的核心争论是：
长期记忆到底应该压缩成结构化 memory，还是保留原始对话、需要时再搜索？

4. Hegel 的判断是：
这个问题不是空白。
SmartSearch、MemMachine、D-Mem、xMemory 等工作都已经碰到了“压缩 vs 原文保真 / 原文回退”的问题。
但你仍然可以做一个本科可落地的版本：
以 SimpleMem 为对象，加入 provenance / source ids，再做 raw episode fallback，系统比较 compressed-only、raw-only、compressed+raw fallback。

5. 最适合当前毕设的题目是：
中文：
面向长期对话问答的可溯源 SimpleMem：语义压缩记忆与原始对话回退检索的权衡研究

英文：
Provenance-aware SimpleMem: Compressed Memory with Raw Episode Fallback for Long-term Conversational QA


二、近期方向总览：大家最近在做什么

1. 从固定 top-k 转向 query-adaptive retrieval。
不是每个问题都检索固定数量的 memory。
系统会根据问题类型、实体、时间、多跳需求动态决定检索策略和上下文预算。

2. 从纯向量检索转向 hybrid retrieval。
长期对话问答里，人名、地点、日期、关系、事件顺序很关键。
所以近期工作普遍结合 semantic retrieval、keyword / BM25、entity、time、graph、reranker。

3. 从“构建更复杂 memory”转向“memory 是否可追踪、可审计、可删除、可更新”。
社区开始更重视 provenance、timestamp、confidence、user isolation、deletion / update。

4. 从“压缩越强越好”转向“压缩与原文保真之间的权衡”。
SimpleMem 代表高密度语义压缩路线。
SmartSearch、MemMachine、D-Mem 则提醒：原始对话和原文 fallback 可能非常重要。

5. 从只看最终答案分数转向 evidence-level evaluation。
只看 F1 或 LLM judge 不够。
更关键的是：正确证据有没有被检索到？证据是在 memory 构建时丢失，还是检索时没找回来？

6. 从研究型 benchmark 走向工程安全问题。
memory poisoning、隐私泄漏、错误记忆锁定、跨用户污染、平台锁定，都是社区讨论中的真实担忧。


三、核心 baseline 和背景论文

1. SimpleMem
链接：
https://arxiv.org/abs/2601.02553
https://github.com/aiming-lab/SimpleMem

定位：
当前项目最重要的 baseline。
SimpleMem 主张把长期对话压缩成高密度文本 memory，再用混合检索回答 LoCoMo 这类长期对话问题。

Hegel 的看法：
SimpleMem 是很适合本科毕设复现和改进的 baseline，因为代码已经在仓库里，主题也非常集中。
但它的问题是：压缩后的 memory 与原始证据之间缺少清晰 provenance。
如果回答错了，很难判断是压缩阶段丢证据、检索阶段没召回，还是生成阶段没用对。

对毕设的启发：
不要直接说“我改进 SimpleMem 成为 SOTA”。
应该说：
在 LoCoMo10 的统一实验协议下，分析 SimpleMem 语义压缩记忆的证据保真问题，并提出 source-grounded fallback。


2. Omni-SimpleMem
链接：
https://arxiv.org/abs/2604.01007

定位：
SimpleMem 的多模态扩展方向。

Hegel 的看法：
它说明 SimpleMem 系列正在向多模态长期记忆扩展。
但对本科毕设来说，不建议一开始做 Omni-SimpleMem。
LoCoMo10 中确实有 image evidence，但多模态会显著增加工程和评测复杂度。

对毕设的启发：
先把 text-only SimpleMem 做扎实。
论文里可以说明当前工作聚焦文本长期记忆，多模态留作未来工作。


四、压缩 vs 原文检索相关工作

这部分最接近用户感兴趣的方向。

1. SmartSearch
链接：
https://arxiv.org/abs/2603.15599

定位：
偏 raw unstructured conversation history retrieval。
它不是先把对话压缩成结构化 memory，而是更强调直接从原始对话历史中做检索、扩展和 rerank。

Hegel 的看法：
SmartSearch 对“复杂 memory 结构一定更好”构成挑战。
它说明原始对话本身，如果配合强检索、实体/关键词处理、多跳扩展和 reranker，可能非常强。

对毕设的启发：
你的实验必须有 raw dialogue retrieval baseline。
否则只和 SimpleMem 内部变体比较，会显得不够有说服力。


2. MemMachine
链接：
https://arxiv.org/abs/2604.04853
GitHub：
https://github.com/MemMachine/MemMachine
文档：
https://docs.memmachine.ai/open_source/introduction

定位：
强调保留 raw conversational episodes，减少 routine LLM extraction。
它更像是“保真存储 + 强 recall / rerank”的路线。

Hegel 的看法：
MemMachine 代表一种反思：
与其在写入阶段过度总结和压缩，不如尽量保留原始事实，重点优化检索和排序。

对毕设的启发：
这支持你做“compressed-only vs raw-only vs compressed+raw fallback”的对照。
特别值得关注的问题是：
当原始 ground truth 被保存下来后，决定性能的可能不是记忆写得多漂亮，而是能否在问题来时准确找到它。


3. D-Mem
链接：
https://arxiv.org/abs/2603.18631

定位：
非常接近“压缩 + 原文回退”的方向。
大致思路是先用快速 memory / 压缩 memory 做 System 1，如果不够，再用更慢但更充分的原文 deliberation 做 System 2。

Hegel 的看法：
这篇说明“compressed memory + raw fallback”这个大方向已经有人做过。
所以你的论文不能写“首次提出压缩和原文回退”。

对毕设的启发：
新意应该放在 SimpleMem-specific：
为 SimpleMem 的 memory entry 增加 source ids；
根据 source ids 展开原始 dialogue window；
在 LoCoMo10 上分析压缩损失和 fallback 恢复能力。


4. xMemory
链接：
https://arxiv.org/abs/2602.02007

定位：
层级 memory。
大致包含 theme / semantic / episode / raw message 等多层，必要时可展开到更原始的信息。

Hegel 的看法：
xMemory 说明近期趋势不是简单选择“只压缩”或“只原文”，而是做层级结构。

对毕设的启发：
你的方案可以被表述为一种轻量层级方案：
SimpleMem compressed memory 是上层；
原始 dialogue window 是下层；
问题复杂或置信度不足时，从上层回到底层。


五、结构化 / 图 / 自适应记忆工作

1. HingeMem
链接：
https://arxiv.org/abs/2604.06845

定位：
关注 person、time、location、topic 等事件边界，以及 query-adaptive retrieval。

Hegel 的看法：
它和方向一关系较近。
长期对话问答中，时间、人物、地点不是装饰信息，而是决定检索是否成功的关键。

对毕设的启发：
SimpleMem 的检索改进不应只做 semantic similarity。
可以加入问题类型、时间词、人名、地点、实体匹配，以及动态 top-k。


2. StructMem
链接：
https://arxiv.org/abs/2604.21748

定位：
结构化 memory 方向。

Hegel 的看法：
这类工作说明大家在尝试把 memory 从纯文本片段变成更结构化的事件、实体、关系。

对毕设的启发：
本科阶段不建议完整复现复杂结构化 memory。
但可以借鉴它的思想：
给 memory entry 增加 provenance、entity、time、topic 等可用于检索和解释的字段。


3. HyperMem
链接：
https://arxiv.org/abs/2604.08256

定位：
更复杂的 memory 组织结构，可能涉及超图或更高阶关系表达。

Hegel 的看法：
这类方向研究感强，但工程复杂度高。

对毕设的启发：
不建议作为主方向。
可以在 related work 里提到，说明你的工作选择了更轻量、更可复现的 SimpleMem provenance 方案。


4. APEX-MEM
链接：
https://arxiv.org/abs/2604.14362

定位：
agent memory / structured memory 相关近期工作。

Hegel 的看法：
代表近期 memory 系统继续向 agent 工作流和结构化管理发展。

对毕设的启发：
不必正面复现。
可以作为“复杂系统型 memory”的相关工作背景。


六、写入、抽取、主动记忆相关工作

1. MemReader
链接：
https://arxiv.org/abs/2604.07877

定位：
关注 memory 读取/写入质量、主动抽取或 reader 机制。

Hegel 的看法：
它提醒我们：memory 问题不只是 retrieval，写入阶段也会造成信息损失。

对毕设的启发：
你的 error analysis 应该区分：
memory construction error；
retrieval error；
generation error。


2. LightMem
链接：
https://arxiv.org/abs/2604.07798

定位：
轻量 memory / efficient memory 方向。

Hegel 的看法：
说明效率仍然是 memory 系统的核心卖点。

对毕设的启发：
不能只报告准确率。
还应该报告 context token 数、retrieval time、fallback rate。


3. All-Mem
链接：
https://arxiv.org/abs/2603.19595

定位：
更广义或统一式 memory 方向。

Hegel 的看法：
近期有不少工作试图提出“大一统 memory 框架”，但本科毕设不适合追求系统大而全。

对毕设的启发：
聚焦一个清楚问题：
SimpleMem 语义压缩是否丢证据，以及 raw fallback 是否能修复。


4. A-MAC
链接：
https://arxiv.org/abs/2603.04549

定位：
agent / memory / action / control 相关方向。

Hegel 的看法：
和长期 agent 记忆生态相关，但不是当前 SimpleMem + LoCoMo 的最直接 baseline。

对毕设的启发：
可以放在 related work，不建议纳入第一阶段实验。


七、benchmark / evaluation 相关工作

1. PERMA
链接：
https://arxiv.org/abs/2603.23231

定位：
长期个性化 / persistent memory 评测相关。

Hegel 的看法：
memory 评测正在从简单事实召回走向个性化、长期一致性、偏好和更新。

对毕设的启发：
本科阶段可以先做 LoCoMo10，但在论文讨论中指出：memory 系统还需要评估更新、遗忘、个性化和隐私。


2. MemoryCD
链接：
https://arxiv.org/abs/2603.25973

定位：
memory consistency / change detection 相关评测。

Hegel 的看法：
这和“错误记忆锁定”有关。
长期记忆系统必须能处理事实变化。

对毕设的启发：
如果时间允许，可以加入一个小分析：
当 memory 中存在过期信息时，SimpleMem 是否会错误使用旧事实？


3. AlpsBench
链接：
https://arxiv.org/abs/2603.26680

定位：
长期 agent / personalization / memory 相关 benchmark。

Hegel 的看法：
说明 memory benchmark 正在扩展，不再只有 LoCoMo。

对毕设的启发：
不建议第一阶段加入太多 benchmark。
先把 LoCoMo10 做透。


4. VehicleMemBench
链接：
https://arxiv.org/abs/2603.23840

定位：
垂直领域 memory benchmark。

Hegel 的看法：
说明 memory 正在走向具体场景。

对毕设的启发：
可以在 related work 中说明：长期记忆不仅是聊天任务，也会进入车载、医疗、办公、代码助手等场景。


八、社区讨论和工程看法

1. Letta Agent Memory
链接：
https://www.letta.com/blog/agent-memory

Hegel 的看法：
社区越来越把 memory 看成 context management，而不是模型权重里的“永久记忆”。
核心问题是存储、检索、压缩、更新、删除和治理。


2. Letta LoCoMo benchmark
链接：
https://www.letta.com/blog/benchmarking-ai-agent-memory

Hegel 的看法：
Letta 用 filesystem / search / open 这类简单可审计工具跑 LoCoMo，并报告了很强结果。
这提醒我们：简单 raw / file baseline 不能被忽视。

对毕设的启发：
你的 baseline 表里必须有 raw dialogue retrieval 或 file-style retrieval。
否则导师可能会问：你怎么证明复杂 memory 真的比直接搜原文好？


3. mem0 memory issue
链接：
https://github.com/mem0ai/mem0/issues/4573

Hegel 的看法：
社区有人报告，真实生产环境里自动抽取 memory 后，大量 memory 变成垃圾、重复、过时、敏感或幻觉内容。
这说明 memory 写入不是越多越好。

对毕设的启发：
可以在论文讨论中写：
长期记忆系统需要 memory quality control，包括 provenance、deduplication、expiration、privacy filtering、delete/update。


4. MCP memory server
链接：
https://github.com/modelcontextprotocol/servers

Hegel 的看法：
memory 正在成为 agent 工程基础设施的一部分。
但基础设施化以后，安全、隔离、迁移、审计会更重要。


九、Hegel 对当前毕设路线的具体建议

1. 不要写“最新长期记忆 SOTA 系统”。
这个说法太大，也容易被审稿或导师追问复现协议。

2. 建议写成：
“以 SimpleMem 为例，研究语义压缩记忆与原始对话检索之间的权衡。”

3. 实验主线建议：
compressed-only：
只用 SimpleMem memory。

raw-only：
直接检索原始 dialogue turns / episodes。

compressed + raw fallback：
先检索 SimpleMem memory，再根据 provenance 找回原始对话窗口。

4. 必须加的指标：
答案 F1；
LLM judge；
retrieval recall@k；
evidence coverage；
retrieval time；
context token count；
fallback rate。

5. 最关键的工程改动：
给 SimpleMem 的 MemoryEntry 增加 source_dialogue_ids / source_turn_ids。
没有 provenance，就无法做 evidence-level evaluation，也无法做 raw episode fallback。

6. 最关键的分析：
不要只报一个总分。
要按问题类型分析：
single-hop；
multi-hop；
temporal；
open-ended；
preference / personal fact。

7. 最可能成立的结论形态：
压缩记忆在简单事实问题上成本低、可能足够；
原始对话在开放式、细节型、语气型问题上更稳；
hybrid fallback 在多跳和时间问题上可能更稳；
但需要用 LoCoMo10 受控实验验证，不能预设。


十、可以直接放进论文 related work 的分类

1. Semantic compression memory
代表：
SimpleMem、Omni-SimpleMem。

关注点：
如何把长对话压缩成高密度、可检索的 memory。

不足：
可能丢失原始证据，且 provenance 不足。


2. Raw conversation retrieval
代表：
SmartSearch、MemMachine、Letta filesystem baseline。

关注点：
尽量保留原始对话，通过搜索、rerank、neighbor expansion 找证据。

不足：
可能上下文成本更高，需要强排序和预算控制。


3. Hybrid / fallback memory
代表：
D-Mem、xMemory，以及你计划做的 Provenance-aware SimpleMem。

关注点：
先用压缩 memory 提供高效线索，再在必要时回到原文。

优势：
兼顾效率、准确率、可解释性。


4. Structured / graph / adaptive memory
代表：
HingeMem、StructMem、HyperMem、APEX-MEM。

关注点：
用实体、时间、事件、关系、图结构组织记忆。

不足：
工程复杂度高，本科毕设不宜一开始全量复现。


5. Memory evaluation and governance
代表：
PERMA、MemoryCD、AlpsBench、VehicleMemBench，以及社区关于 memory safety / junk memory 的讨论。

关注点：
memory 不只是召回事实，还要处理更新、遗忘、隐私、安全、跨用户隔离和审计。


十一、最终建议

Hegel 的最终建议是：
你的毕设不要追求“大而全的长期记忆系统”，而要抓住一个小但锋利的问题：

SimpleMem 把长期对话压缩成 memory entries，这个压缩到底是否保留了回答问题所需的证据？
如果没有保留，能不能通过 provenance 找回原始对话窗口？
这种 compressed memory、raw retrieval、compressed+raw fallback 的权衡，在不同问题类型上有什么规律？

这个问题足够具体，和当前仓库强相关，也能和最近两个月 memory 领域的讨论对上。
